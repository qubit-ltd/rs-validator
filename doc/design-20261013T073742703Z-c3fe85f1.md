# README 安装路径与示例验证设计

## 背景与证据

本设计针对 2026-10-13 对 `rs-validator` 的综合评审中确认的唯一改进项。当前 `README.md` 和 `README.zh_CN.md` 的安装段给出 `qubit-validator = "0.1"`、`qubit-model-metadata = "0.2"`、`qubit-model-derive = "0.2"`、`qubit-reflect = "0.2"`，随后将依赖模型注解的程序称为可直接运行的快速开始。当前 checkout 中，`rs-model-metadata/Cargo.toml` 和 `rs-model-metadata/derive/Cargo.toml` 均声明 `publish = false`。因此，README 的纯版本号安装说明无法由当前仓库状态证明可复现；`rs-validator` 自身的测试也不编译这两份 README 中的完整程序。

现有 `examples/local_registry.rs` 和 Rustdoc 已展示无需模型元数据的绑定路径；`rs-model-metadata` 则有模型级校验文档及跨 crate 文档示例测试。问题位于入门路径和验证边界，不要求调整 `qubit-validator` 的公开 API、执行语义或分层架构。

## 目标

1. 两版 README 的首个安装命令只包含其完整快速开始实际需要的依赖，并让读者能复制代码、运行程序、观察有效与无效输入及保存决策。
2. 继续说明模型字段注解的跨项目集成，但明确它是进阶路径，以及同一 checkout 下的路径依赖和必要项目布局；不声称当前未发布的下游 crate 可仅凭版本号安装。
3. 在 `rs-validator` 自身的测试中编译并运行两版 README 的快速开始，防止文字、依赖和代码再次漂移。
4. 更新两版用户指南中指向旧 README 注解示例的文字与链接，使读者能找到正确的进阶入口。

## 方案与取舍

采用**独立可运行的核心快速开始 + 明示路径依赖的进阶集成**。README 的主示例保留“用户注册时拒绝空白姓名、合法输入才写入”的场景，但由应用显式调用 `ValidatorRegistry::bind`、`BoundValidator::validate` 和 `ValidationReport::record_outcome`，只依赖 `qubit-validator`。模型注解的执行、对象遍历和规则调度仍归 `qubit-model-metadata`，README 用短节解释何时采用，并链接其双语用户指南。

曾考虑保留现有跨 crate 程序作为首页快速开始并改成路径依赖。这样会让首个示例依赖多个同级 checkout，且独立的 `rs-validator` CI 无法稳定编译它。也考虑只加一句“依赖未发布”；这不能验证程序，也不能让当前安装说明可执行。选定方案优先保证本 crate 的首次使用路径独立可测，同时保留真实的跨项目演进方向。

## 文档契约

- `README.md` 与 `README.zh_CN.md` 的 Installation/安装节都保留 `qubit-validator = "0.1"` 作为仅使用本 crate 的版本依赖，适用 Rust 1.94 及以上。快速开始的完整代码只使用该依赖的公开 API 与标准库。
- 两版快速开始使用相同的 Rust 程序，包含两条规则注册、启动时绑定、一次无效请求、一次有效请求、报告完整性检查、按字段路径展示违规代码，以及可观察的零次/一次存储写入。示例不记录被拒绝的原始输入；应用明确负责字段选择、调用顺序和保存。
- 两版 README 增设简短的“模型注解集成 / Model annotations”进阶节。该节说明 `qubit-model-metadata` 与 `qubit-model-derive` 在当前 checkout 为 `publish = false`，给出同一 checkout 的路径依赖示意。示意以布局 `<checkout>/rust-common/{rs-validator,rs-model-metadata,rs-reflect,rs-validation-rules}`、应用目录 `<checkout>/app` 为前提；路径从应用的 `Cargo.toml` 所在目录计算。示意为本地开发路径，不称为 crates.io 安装命令。模型级完整示例和支持范围链接至 `rs-model-metadata` 的双语用户指南。
- 两版用户指南的相关链接从旧 README 注解快速开始改为该进阶节或模型校验指南；直接绑定与报告的教程保持不变。
- 两版语言在依赖、行为、限制和链接上语义一致；中文自然表达，不逐句翻译。

## 示例验证机制

新增 `tests/documentation_examples_tests.rs`，作为普通 Cargo 集成测试运行，不依赖同级仓库。README 在安装 TOML 与快速开始 Rust 代码块前各放一个稳定的非渲染标记，测试按标记提取对应 fenced block；标记缺失、重复、代码块语言错误、安装项不等于 `qubit-validator = "0.1"` 均使测试失败。

测试分别把英文和中文代码块写入各自独立的临时 Cargo 应用。它仅在测试夹具中把版本依赖替换为当前 `rs-validator` 的绝对路径，以验证本次 checkout 的 API；README 本身保留真实版本语法。夹具执行 `cargo run --offline --quiet`，程序内部断言拒绝与通过两条路径、报告字段和写入次数。测试只删除自己创建的临时应用目录；构建缓存可重用。`--offline` 的可行性来自外层 `cargo test` 已解析本 crate 依赖；如 CI 环境证明缓存隔离，则使用同一 Cargo home 的在线 `cargo run --quiet`，不能跳过测试。新夹具尚无锁文件，不使用 `--locked`。

该测试证明示例代码与本地 crate 可一起运行；它不证明远端 registry 在任何时刻都提供指定版本。因此 README 不对未验证的远端发布状态作承诺。

## 边界与风险

- 不修改生产 Rust 代码、公共 API、现有规则语义或下游仓库。允许替换现有 README 注解示例，因为用户已允许破坏性变更，但不改变 crate 对消费者的契约。
- 临时 Cargo 夹具会增加测试时间；只为两版 README 各运行一次，不在每个 feature 组合中另建不同示例。CI 原有的默认与 `inventory` feature 测试可复用同一测试代码。
- 本地路径示意依赖明确的目录布局；移动 checkout 时应重新计算路径。跨仓库的模型示例由模型元数据项目自己的文档示例测试负责，`rs-validator` 的测试只覆盖自己的独立入门路径。

## 验收标准

1. 两版 README 的安装段、快速开始、模型集成说明互相一致；只复制主安装段与程序即可在本 crate checkout 对应的测试夹具中运行。
2. `cargo test --test documentation_examples_tests --locked` 通过，并确实分别执行两版 README 的程序；任意一版删除标记、改坏依赖或破坏公开 API 调用时，该测试失败。
3. `cargo test --no-default-features --locked`、`cargo test --all-features --locked`、项目格式检查及相关文档链接检查通过；目标工作树的最终 diff 仅涉及本设计列明的文档和示例测试。
