# rs-validator 参数绑定契约与文档验证设计

## 背景与证据

本设计落实 2026-10-13 综合评审中已接受的四项意见。当前 `PrepareFn` 接收原始 `&[NamedValidationArgument]`；`ValidatorDescriptor::bind` 和 `bind_for_validated` 直接调用工厂，仅在调用后检查预备验证器的输入与依赖形状。工厂若忽略参数，重复或未知参数可静默通过。`ArgumentReader` 已具备重复名检查、一次性读取与 `finish()` 未消费参数检查，但现有 API 没有要求工厂使用它。`PrepareFn` Rustdoc 对参数错误的无条件承诺因此不成立。

`ExecutionError::with_trusted_source` 可保留任意拥有型底层错误，`trusted_source()` 可显式读取；默认 `Display`、`Debug` 与标准 `Error::source()` 不披露它。中英文 `doc/design*` 同时写有“执行错误绝不保留被拒绝输入”，与公开 API 和 `tests/security/redaction_tests.rs` 的测试相矛盾。

`tests/documentation_examples_tests.rs` 已运行两版 README 快速开始，却没有编译两版用户指南的组合示例。另有六个返回 `Result` 的方法重复标注函数级 `#[must_use]`，与项目 Rust 风格规则不一致。

## 目标与边界

1. 经 `ValidatorDescriptor` 或 `ValidatorRegistry` 绑定时，重复参数名与未消费参数必定被拒绝，工厂不能绕过；已消费参数的类型、范围及规则特有必填条件仍由工厂判断。
2. 公开 API、Rustdoc、双语 README、双语用户指南和双语设计文档准确说明同一参数契约与脱敏边界。
3. 自动编译两版用户指南的基础接入代码；继续运行两版 README 程序和现有 Rustdoc 示例。
4. 只修正评审指出的冗余 `#[must_use]`，不顺带改写其他实现。

用户允许破坏性变更。本设计不保留旧 `PrepareFn` 签名的兼容层；本轮产物仅为设计和计划，实施由后续执行者完成。

## 方案选择

选择**绑定层持有 `ArgumentReader`，工厂只拿可变 reader**。对比过两种方案：只修订 Rustdoc 能消除错误承诺，却保留配置拼写错误被静默接受的风险；给每个 `ValidatorSignature` 增加完整参数 schema 能在工厂前做全部检查，但会重复规则自己的类型与条件判断，扩大声明面。所选方案复用现有一次性消费机制，集中保证重复与未知参数检查，保持必填及语义约束在工厂内。

### 公共接口

将类型别名改为：

```rust
pub type PrepareFn = for<'a> fn(&mut ArgumentReader<'a>)
    -> Result<Arc<dyn PreparedValidator>, BindError>;
```

`ValidatorSignature::new` 仍接收 `PrepareFn`，`ValidatorDescriptor::{bind, bind_for}` 与 `ValidatorRegistry::bind` 仍由调用方提供 `NamedValidationArgument` 切片。绑定层把该切片借给一个 reader；工厂使用 `reader.required_u32("maximum")?` 一类方法取得规则所需参数，并把需要跨绑定调用存活的数据转为预备实例自己拥有的值。`ArgumentReader::new` 仍可供直接使用，不删除 `finish()`；增加 `required_argument(name)` 以支持按名称消费任意 `ValidationArgument` 变体，适用于需要保留并检查全部原始参数种类的消费者。直接调用 reader 或工厂时，调用方自行决定何时完成检查。**经描述符或注册表绑定**才保证自动 `finish()`。`PrepareFn` 的旧切片签名删除，不设置弃用期。

### 绑定时序和错误

1. 保持已有描述符与签名选择检查。
2. 绑定层调用 `ArgumentReader::new(params)`，重复名立即返回 `DuplicateParameter`，并附带规则 ID。
3. 绑定层调用所选工厂，工厂通过 `required_*`、`optional_*` 读取声明参数；其类型、范围、缺失或领域约束错误保持原类别和规则 ID。
4. 工厂成功返回后，绑定层调用 `reader.finish()`；任何未读参数返回 `UnknownParameter`，附带规则 ID。预备实例随错误被丢弃，不产生 `BoundValidator`。
5. 最后检查预备实例的输入与依赖形状，再构造 `BoundValidator`。因此同一次调用既有未知参数又有预备形状错误时，先报告未知参数；工厂自身报错时不再执行 `finish()`。

把第 2–5 步收敛到 `ValidatorDescriptor` 内一个私有 helper，供 `bind` 与 `bind_for_validated` 复用，避免两个入口出现不同的校验顺序。空参数用零长度 consumed 向量，不新增堆分配。签名仍不声明参数 schema，所以框架**不能**判断工厂忘记读取的必填参数；公开文档必须明确这一剩余职责，不能承诺任意工厂都会拒绝缺失项。

### 下游迁移

`rs-validator` 内全部作为 `ValidatorSignature::new` 第三个参数使用的工厂、Rustdoc 示例、README 程序、`examples/` 与测试 fixture 改为 `&mut ArgumentReader<'_>`。无需参数的工厂可忽略 reader；绑定层的 `finish()` 会拒绝任意实参。需要参数的工厂直接读取 reader，移除其内部重复的 `ArgumentReader::new` 与 `finish()`。

实际下游签名声明位于 `rs-validation-rules/src/registry/{collection,decimal,regex,text,time}.rs`；其 `no_args` helper 也迁移为接受 reader，不在 helper 内结束读取。签名搜索还发现 `rs-model-metadata` 与 `rs-model-metadata-v3` 的测试和运行时 fixture 自行声明 `ValidatorSignature`，需要同步迁移这些消费者工厂。两个 metadata 仓库仅调整工厂 fixture，不改变生产行为；保留原有未提交工作树内容。

## 文档与示例验证

### 参数与脱敏文案

- `PrepareFn`、`ValidatorDescriptor`、`ArgumentReader` 的 Rustdoc，以及中英文 README、用户指南、设计文档，对齐“绑定层保证重复和未消费参数；工厂保证必填、类型、范围与领域条件”。更新所有工厂示例，保持中英文语义一致。
- 中英文 `doc/design*` 的目标与脱敏段改为：普通格式化、标准错误链和结构化报告不自动暴露原始输入；`trusted_source()` 可保留并向显式调用者提供底层原因，调用方必须控制其来源和访问权限。保留“违规参数来源由调用方负责”的既有说明，不再写“执行错误绝不保留”。`ExecutionError` 本身不变；既有敏感原因测试继续作为证据。

### 两版用户指南的基础路径

在两版 `doc/user_guide*` 的四段基础代码块前分别放稳定 HTML 标记：`rules`、`startup`、`service`、`service-continuation`。文档测试提取每版恰好一份对应 fenced Rust 块，按注释标注的文件布局写入独立临时 Cargo 应用：`rules.rs`、`startup.rs` 和由两段拼接成的 `service.rs`。补充最小 `src/profile/mod.rs` 与 `src/main.rs`，用本地路径依赖执行 `cargo check --offline --quiet`。该检查只证明基础路径能组合编译，不声称进阶章节或外部存储实现已经运行；README 的程序测试仍证明有效与拒绝分支的执行结果。若基础路径中的规则接口发生变化，两版指南及其测试须同步调整。

文档测试沿用现有 `TemporaryApp` 的唯一目录与自有 `CARGO_TARGET_DIR`；测试失败要指出语言、代码块标记和 Cargo stderr。两种语言分别编译，防止一版更新掩盖另一版漂移。不要将生产指南改写成测试 fixture，也不复制完整指南代码到测试源。

## 风格修正

移除 `BoundValidator::try_from_prepared` 和 `BoundValidationContext::{value,dependency_path,typed,optional_typed,text}` 上与返回 `Result` 重复的函数级 `#[must_use]`。保持签名、行为和文档含义；不为此添加镜像实现的测试。

## 验收标准

1. 对 `ValidatorDescriptor::bind`、`bind_for` 和 `ValidatorRegistry::bind` 的代表路径，测试证实忽略 reader 的工厂也无法接受重复或未知参数；工厂的必填、类型、范围错误及规则 ID 保持正确。
2. `rs-validator` 默认与 `inventory` feature 的测试、doctest、全目标编译和项目风格检查通过；两版 README 程序照常运行，两版用户指南基础代码独立组合编译。
3. `rs-validation-rules` 与 `rs-model-metadata` 的相关 feature 编译通过；下游迁移后的本地集成测试覆盖至少一条有参规则和一条无参规则。
4. 双语文档不再对 `PrepareFn` 的任意实现或 `ExecutionError` 的内部保留行为作过强承诺；链接、代码标识符、示例签名一致。
5. 最终改动仅包含上述契约、必要消费者迁移、测试与文档。实施前后检查工作树；不在本设计授权之外执行 `git add`、`git commit` 或 `git push`。
